# Product

## Register

product

## Users

Algora serves students, self-taught developers, and interview candidates who need to understand how a data structure changes during an operation. They use it on laptops during focused study and on phones for quick revision. Their main job is to connect code, state changes, and complexity without mentally simulating every step.

## Product Purpose

Algora turns data structures and algorithms into inspectable traces. A learner can provide input, run an operation, pause at any step, and see the data, pseudocode, and explanation stay synchronized. Success means a learner can explain both what changed and why it changed after using a visualizer.

## Brand Personality

Precise, calm, and encouraging. The voice is direct and technically credible without sounding academic or cold. The interface should create confidence through clarity, not through decoration.

## Anti-references

- Generic developer dashboards filled with unrelated cards and decorative metrics.
- Neon cyberpunk algorithm tools that sacrifice legibility for atmosphere.
- Tutorial sites that separate prose, code, and examples into disconnected pages.
- Interfaces with novelty controls, heavy glass effects, purple gradients, or motion that delays the task.

## Design Principles

1. Keep cause and effect together. The structure, active code line, and explanation must describe the same moment.
2. Make the next action obvious. A first-time learner should be able to run a useful trace without reading documentation.
3. Preserve context on small screens. Mobile layouts may stack or collapse regions, but must keep playback and the active state reachable.
4. Teach through state. Labels, highlights, and visit order should explain the algorithm instead of merely animating it.
5. Earn complexity. Reusable engines and pure algorithms should support rich interactions without duplicating logic between screens.

## Accessibility & Inclusion

Target WCAG 2.2 AA. All operations must work with keyboard input, focus must remain visible, status changes must be announced, and meaning must never depend on color alone. Touch targets should be at least 44 by 44 pixels on mobile. Reduced motion, light and dark color schemes, zoom to 200 percent, and narrow screens are first-class requirements.
